# EXPERIENCE

Lessons from traps that actually cost time. One line each: trap → rule.

- **`@ts-expect-error` placement:** a directive on a multi-line `//` comment binds to the comment's second line, so it reports "unused" and you conclude the type is permissive when it is not -> keep the directive on a single line immediately above the code under test.
- **`@cline/sdk` declarations decay under `skipLibCheck`:** `AgentPlugin` and `CoreSessionConfig` accept objects missing their own required fields, and `ClineCore.start()` resolves to `unknown` (TS2834 forces `skipLibCheck`) -> never validate an SDK object by type; validate at the boundary with our own zod and declare a local interface for the slice we call.
- **`pluginPaths` does not load candidate plugins:** a `.ts` file or its bare directory both register nothing -> import the plugin ourselves and inject it via `extensions: [pluginObject]`, then assert the declared tools actually appeared.
- **Secret redaction misses transformed values:** `coerce` trims before reporting, so redacting only the raw key leaves the trimmed substring in the error -> register raw + trimmed + JSON-escaped variants and replace longest-first.
- **`config.skills` is not a visibility gate:** a skill under `<cwd>/.cline/skills/<name>/SKILL.md` appears even with an empty list, and its body is never inlined into the request -> scope c6 by which directories exist, and budget for a tool entry rather than the file body.
- **Over-redaction from placeholder credentials:** a leftover `OPENAI_API_KEY=1` makes `redact` replace every `1`, turning `b1Tokens` into `b<redacted>Tokens` and hiding the real error -> skip redaction candidates shorter than 4 chars; no real key is that short.
- **Whitespace-only env vars are not "unset" by default:** a `!== ""` check lets `SYNTHETIC_API_KEY="   "` win the chain and then fail coercion, while the provenance field already reported it as absent -> test `.trim() !== ""` in every place that reads a chain (value, provenance, retired-name check).
- **`in` is not key presence:** `"toString" in {}` is `true` through `Object.prototype`, so a file legally named `toString` made a deletion look real and a diff look modified -> use `Object.hasOwn` for every key-membership test on a record keyed by user data.
- **A single `read` can return short:** treating one `handle.read` as the whole file silently truncates, and a `stat.size + 1` buffer cannot detect growth either -> loop until EOF into capped 64 KiB chunks.
- **`readdir` decodes filenames lossily:** raw bytes `FF` and `EF BF BD` both decode to `U+FFFD` and merge into one key after validation -> read names as buffers (`encoding: "buffer"`) and strict-decode before validating.
- **Resolve the *endpoint* of a link chain, not just the root:** on macOS `/var` is a symlink to `/private/var`, so a `realpath`ed root compared against an unresolved `path.resolve`d target reports `SYMLINK_OUTSIDE_ROOTS` for a perfectly legal SSOT link -> `realpath` both roots *and* the chain endpoint before any `path.relative` containment test.
- **A pruned-subtree assertion cannot prove a walk never happened:** asserting "`node_modules` is absent from the tree" passes equally for "never visited" and "visited then filtered" -> wrap `fsPromises.readdir` and assert no listed path contains the pruned segment.
- **`path.resolve` is wrong for a symlink target:** `alias/../x.md` where `alias -> real/subdir` resolves lexically to `x.md` but the kernel reads `real/x.md` -> consume the path component by component and pop `..` off the *resolved* stack.
- **`path.relative(root, root)` is `""`, not `".."`:** a containment helper that returns null for the root itself silently reports "outside" for a link whose parent *is* the root -> keep "strictly inside" and "at or inside" as separate questions.
- **A cycle key must describe resolution state, not depth:** keying visited links on `queue.length` misses `a -> a/b` (which deepens the queue every pass) and rejects `alias/../alias/x` -> keep a stack of *active* expansions and call a revisit of an active link a cycle, with an absolute expansion cap as the backstop.
- **Dropping `.` and trailing `/` loses a kernel requirement:** `splitPath` normalises `file.md/.` and `file.md/` to `file.md`, which then reads as a file where the kernel raises `ENOTDIR` -> carry the "must be a directory" requirement as an explicit queue marker.
- **A session id you did not supply is an id you cannot abort:** `StartSessionResult.sessionId` only exists after `start()` resolves, so a hung first turn has nothing to cancel -> pass `sessionId` in the start config and `abort()` with that on timeout.
- **`@cline/sdk` is a one-line re-export of `@cline/core`:** `node_modules/@cline/sdk/dist/index.d.ts` is 64 bytes, so grepping it for `CoreSessionConfig` finds nothing -> read the real surface under `.pnpm/@cline+core@*/node_modules/@cline/core/dist`.
- **`node:test`'s `it` takes options before the function:** `it(name, fn, { timeout })` fails typecheck because that overload reads the function as `TestOptions` -> `it(name, { timeout }, fn)`.
- **A queued writer must gate at submit, not inside the task:** checking "am I writable" inside the queued callback makes `close()` (which sets `closing` before draining) reject work it had already accepted -> check at submission, drain the queue, and memoise one `close()` promise so two shutdown paths cannot both `rm` the lock.
- **`FileHandle.write` may write less than asked:** resolving means "this many bytes", not "all of them" -> loop over a `Buffer` with `offset`/`length` and poison the writer on zero progress, or a short write silently glues the next JSON line onto a truncated one.
- **Cline's editor tool rejects payloads over ~6 kB:** a whole-file create fails with "input too large" and nothing is written -> create the file with its first section, then append the rest in follow-up edits.
- **`@cline/core`'s command wrapper leaves a 30 s timer running:** a *successful* `run_commands` keeps the process alive until it expires (`Promise.race` without `clearTimeout`) -> in a short-lived live child, write the result and `process.exit(0)` from the write callback instead of waiting for the event loop to drain.
- **Any live session now needs an evidence file:** the claim gate requires `B5.hooks` for every run, and `.tmp/spike-evidence.json` is gitignored -> tests and children call `writeEvidence()` from `test/support/evidence-fixture.ts` with the installed SDK version.
- **A loser of `Promise.race` is not an unhandled rejection:** the race subscribes to every entrant, so a `start()` that rejects *after* the deadline won is already handled -> do not add a redundant `.catch()` to silence it; test it instead, or the "fix" hides a real one later.
- **Normalising before hashing loses real edits:** rendering terminates a body that lacks a trailing newline, so `"rule"` and `"rule\n"` produce identical prompt text -> hash the raw `{path, body}` entries as well, or an edit to a rule file leaves `compiledPromptHash` unchanged.
- **A caller-owned object is not a snapshot:** `HarnessTree` is a plain object handed in by the caller, and every check is separated from the write by at least one await -> copy it at entry (`{...tree}`) and use the copy, or a mutation during the await writes a harness the fingerprint never described.
- **Two schemas describing the same value will disagree:** `baselineFingerprintSchema.baseSha` accepted 40 *or* 64 hex characters while `probeFingerprintSchema` accepted only 40 -> share one `gitObjectIdSchema`, or a faithfully captured SHA-256 baseline cannot compose into a fingerprint.
- **A fence a body can forge is not a boundary:** `<<<path>>>` delimiters stop neighbouring files running together, but a body containing a fence-shaped line can close its own block and impersonate the next file -> refuse `^<<<` at line start in `renderBlock`.
- **A zero-character slice still needs its bytes in the digest:** the `skills` slice renders no text, so hashing only its entry paths made a `SKILL.md` body edit invisible to `compiledPromptHash` -> keep the definition body in the slice entries; list companions by path and let `Skill.sha256` cover them.
- **Summing a declared inventory and a built-in double-counts it:** a tree that ships `tools/skills.md` *and* a mounted skill was charged two entries for one tool -> count the union of names, not `tools.length + 1`.
- **`afterTool` fires for refused calls:** a phase counter reads as proof of execution and is not -> count `afterToolOnSkipped` separately, pair calls by id (`toolCall.id`/`callId`/`toolCallId`), and consume the skip on first use.
- **Importing an SDK module is a side effect:** `createTool` pulled from `@cline/sdk` at module scope initialises SDK state during pre-flight -> inject the factory and build the plugin after the loader runs but before `createCore`.



- **`run.finished` totals are re-derived, not trusted:** a child ledger that reported `physicalAttempts: 1` with no execution events failed replay with "totals disagree" -> write the real lifecycle (`execution.started`, `attempt.recorded`, `execution.finished`) before the terminal event.
- **A rejected start promise nobody awaits crashes the parent:** aborting a child before `withDeadline` registers its guard left the start rejection unhandled and node:test failed the run -> attach `start.catch(() => undefined)` the moment the promise exists, before any early return.
- **`ClineCore.create({})` is not the same runtime as the parent's:** auto-discovered hub drops inline `localRuntime.extensions`, so a spawned child silently lost its contract plugin -> pass `backendMode: "local"` (plus `clientName` and a per-child `distinctId`) exactly as the parent does.
- **A target budget that ignores the retained prefix is a false `fits`:** subtracting only fixed text + tail reported `fits` for a 105k target while the task message alone was 110k -> subtract `total - eligible` (fixed + tail + task + system), so the budget is what is left after everything rewriting cannot touch.
- **Splitting a tool pair is easy when ids are partial:** id-matching a turn where only some calls carry ids makes an id-less call's own result look foreign -> use id matching only when every call has one, else group positionally and over-preserve.
- **A summariser that only reads `content` loses the work:** an assistant turn with prose *and* `tool_calls` contributed only its preamble -> render the calls into the summariser's text too, or the summary describes intent and not actions.
- **Hoisting one summary over non-contiguous candidates inverts history:** a system message mid-conversation creates two candidate runs, and a single summary placed at the first run moved later turns in front of retained ones -> collapse one contiguous run at a time, each in place.
- **A CLI's stdout is not its reply:** `gemini-api --stream=false` prints the answer and a usage report on one stream, and `codex exec` prints a session preamble before its answer -> read the structured channel instead (`--output-format json` then the `model_output` steps; `codex exec -o <file>` then the last message).
- **A fence-shaped format spec trips your own fence guard:** the oracle client refuses an ask containing a line starting with `<<<`, so a prompt telling the model to emit `<<<proposal:x>>>` blocks was rejected as prompt injection -> describe delimiters inline (`` `<<<proposal:PATH>>>` `` mid-sentence); keep the guard, rewrite the spec.
- **`\s` after a label in a `/m` regex eats the newline:** `^CUE:\s*(.+)$` matches `CUE:` + blank line + next line, so one line can populate two fields -> use `[^\S\r\n]*` for horizontal-only whitespace, and count `matchAll` hits so a duplicate label is refused instead of silently resolved.
- **tsx will not load through `module.register`:** registering `tsx/esm` in-process throws "tsx must be loaded with --import instead of --loader" on Node 23, so a `.ts` CLI cannot be bootstrapped from an `.mjs` shim -> re-exec `node --import tsx <entry>` from the shim and keep the TS entry side-effect free.
- **A re-based baseline must move exactly one field:** after an accepted improvement the tree no longer matches `baselineSha`, so re-capture or rebuild the fingerprint from the previous one and change only `treeSha` -> recomputing the whole fingerprint from scratch silently re-derives the SSOT association list as `[]` and claims the repo links to nothing.
- **`4k` executions vs `3k` improvements:** making either counter terminal means a `k=1` run stops at 3 executions, because one improvement per execution spends `3k` first -> improvements are work the run chose to do, so a spent improvement budget only stops improving.
- **Close the operation last:** `recordOverflowRecovery` appends an attempt against the open execution, so T4 must run before `execution.finished` -> closing first turns every recoverable overflow into a replay rejection.
